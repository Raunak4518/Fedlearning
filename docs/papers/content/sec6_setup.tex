\section{Study design}\label{sec:setup}

The study tests the analysis of \cref{sec:analysis} and the method of \cref{sec:method} on the problem of
\cref{sec:setting}: clients with different head architectures and long-tailed, skewed label distributions.

\subsection{Research questions}\label{sec:setup-rq}

All experiments use the same client splits for every method.
\begin{itemize}
\item \textbf{RQ1 (diagnosis).} Do the three losses of \cref{sec:analysis} occur in GeFL-F's own runs (class-row
norms, readout gain and logit spread)?
\item \textbf{RQ2 (effect).} Does \ours, which ends with the exact readout, raise balanced accuracy over GeFL-F and the
other methods that work with different client models, each without the readout (\cref{sec:res-main}\whentab{k50_bal}{, also
with 50 clients})?
\item \textbf{RQ3 (representation or last layer).} How much of the difference remains when every method of the
GeFL-F pipeline gets the same exact readout, so that only the heads' bodies differ (\cref{sec:res-main},
\cref{tab:readout})?
\item \textbf{RQ4 (scope).} Does the effect hold with natural class imbalance,\whentab{robust}{ with other client
numbers, label skews and imbalance ratios,} and in the standard protocol with one model shared by all clients
(\cref{sec:res-natural,sec:res-shared}\whentab{robust}{, \cref{tab:robust}})?
\whenanytab{abl_bal,abl_components}{\item \textbf{RQ5 (components).} Which changes to GeFL-F carry the effect
(\cref{sec:res-ablation})?}
\end{itemize}
Cost and calibration are reported for every method as secondary outcomes.

\subsection{System under evaluation}\label{sec:setup-system}

\ours keeps the three-stage pipeline of GeFL-F (\cref{sec:setting}), in which the frozen extractor computes every
image's features once, without augmentation. It changes five things in this pipeline (items 1--5) and adds a last step
(item 6; \cref{sec:method}):
\begin{enumerate}
\item the generator, which is anchored to the exact class means, or uses class rows averaged by CCWA when the gate
finds the classes poorly separated;
\item the moment correction of generated features;
\item logit adjustment in the real phase;
\item consensus soft labels in the synthetic phase;
\item the number of synthetic epochs per round, $T_s=10$ instead of GeFL-F's 1;
\item the exact readout of \cref{sec:method-readout}, which sets every last layer after Stage III.
\end{enumerate}
\Cref{tab:hyper} lists the settings of \ours, which are the same on every dataset. The extractor and the ten head
architectures, CNN-1 to CNN-10 (one to four convolutional blocks of different widths and a linear last layer), follow
GeFL-F~\cite{kang2025gefl}; \cref{app:protocol} gives their layers.

\subsection{Datasets and client splits}\label{sec:setup-data}

\paragraph{Long-tailed benchmarks} \R{main/datasets_cite} are made long-tailed by our construction: GeFL-F's
fraction of the training set~\cite{kang2025gefl} is divided over the classes by the profile of \cref{sec:setting}
with $\rho=100$ (GeFL's own splits are balanced). The fraction is GeFL-F's on CIFAR-10
(0.5)\whennum{main/mnist/FedECS-LT/bal}{, MNIST (0.1)}\whennum{main/fmnist/FedECS-LT/bal}{, Fashion-MNIST (0.1)}\whennum{main/svhn/FedECS-LT/bal}{, SVHN (0.1)}. GeFL does not use CIFAR-100; there we take 0.22, which gives the usual CIFAR-100-LT shape. No class receives more
images than remain after the validation images are held out. On CIFAR-10-LT and CIFAR-100-LT the profile asks for more
than that for the largest classes, which are therefore capped. So the realised ratio between the largest and the
smallest class is below 100 (\cref{tab:datasets}); we name every setting by its $\rho$. The class index orders the
classes from the most to the least frequent, so the tail classes are the same in every run.

\paragraph{Natural imbalance} \R{nat/datasets_cite} keep their own class sizes, with training sets capped at 20,000
images. Their classes are relabelled by training frequency. On three of them the realised ratio is small
(\cref{tab:datasets}): their results speak to label skew more than to a long tail.

\paragraph{Splits} The training images are split among $K=10$ clients by a Dirichlet draw with $\alpha=0.5$ per
class. The draw is repeated, at most 100 times, until every client holds at least ten images; if it still fails, random
images move from the largest to the smallest client. Client $k$ trains head architecture $k$, so
in the main setting each architecture has one client.

A held-out block of training images that no client holds forms a validation set: $\min(200,\lfloor 2000/C\rfloor)$
images per class, and at most a quarter of a class with natural imbalance. It has two uses: it trains the classifier
that scores generated features in the diagnostics (\cref{app:fidelity}), and it sets the public bounds by which secure aggregation scales the
released vectors. It is never used to select a model or a hyperparameter. The other unused training images are
discarded. Every result is on the official test set. We checked that the class counts of every client are identical across methods for every dataset and seed.

\subsection{Protocols}\label{sec:setup-protocols}

\paragraph{Main setting: different client models} The main setting is GeFL-F's setting with $K=10$ clients, one
per architecture, at $\rho=100$ and Dirichlet $\alpha=0.5$. The ratio sets the target profile; where a
frequent class has fewer images than the profile asks for, it keeps all of them, so the realised ratio of the
training set can be lower (\cref{tab:datasets}, last column). The rounds of the three
stages, $T_{\mathrm{I}}$, $T_{\mathrm{II}}$ and $T_{\mathrm{III}}$, are GeFL-F's: 50, 200 and 100 on CIFAR-10, and the same on CIFAR-100
(\cref{app:protocol} lists every dataset). All federated methods of this setting share the same Stage-I extractor for
a given dataset and seed: Stage I is computed once and reused.\whentab{k50_bal}{ GeFL's second setting has $K=50$
clients, five per architecture (\cref{sec:res-main}); every method of the main comparison is run there too.}

\paragraph{One shared model} We follow the FedLTLib protocol~\cite{lin2026fedltlib}, whose training settings come
from CReFF~\cite{shang2022creff}: CIFAR-10-LT and CIFAR-100-LT with
the standard profile $n_c=\lfloor n_{\max}\rho^{-c/(C-1)}\rfloor$ at $\rho=100$\numelse{t2/cifar10-r10/FedECS-LT/bal}{ (and 50 and 10)}{}, where $n_{\max}$ is the
number of images per class left after 200 per class (20 on CIFAR-100) are held out for validation. Rounding down gives
the smallest CIFAR-100 class 4 images at $\rho=100$.

There are 20 clients, Dirichlet $\alpha=0.5$, and 8 clients (40\%) take part in each round. All share one
ResNet-8~\cite{he2016resnet}, trained for 200 rounds of 10 local epochs with batch size 32 and SGD (learning rate 0.1,
momentum 0.9, decay 0.99 per round). The baselines run the authors' LongTailLib training code unchanged, on our
splits, with the backbone set to ResNet-8 for every method (the library defaults to ResNet-18 or ResNet-20 for
FedLoGe, Fed-GraB, FedYoYo and FedETF); we evaluate them every fifth round and score Fed-GraB with its trained
classifier.

For \ours the ResNet-8 is split after its second stage into a frozen extractor and a head. The extractor is trained
for 100 rounds with the protocol's local updates, the generator for 100 rounds, and the head for 100 rounds with 10
real epochs per round; the learning-rate decay continues from the extractor's rounds. So \ours uses the baselines'
200 training rounds plus 100 generator rounds. Its head trains on frozen features of images without augmentation,
whereas the baselines train end to end with augmentation. With one architecture, the consensus soft label is the
current shared model's own prediction. \ours averages the clients' models with equal weights, as in the main setting;
the benchmark's FedAvg weights them by their numbers of samples. The clients of each round are a seeded subset; the
library draws its own, so participation is not paired between \ours and the baselines.

\subsection{Methods compared}\label{sec:setup-methods}

\Cref{tab:baselines} lists every method, its reference and the origin of its code, and \cref{tab:fairness} what each
method of the main setting exchanges and computes. The methods fall into these groups.
\begin{itemize}
\item \textbf{GeFL-F}, the method \ours extends: the difference to it answers RQ2 directly.
\item \textbf{FedDF}~\cite{lin2020feddf}, ensemble distillation on the server. GeFL distils on public data; we
run FedDF's distillation on GeFL-F's generated features instead, so that no method uses extra data.
\item \textbf{Per-client long-tail losses}: Balanced Softmax~\cite{ren2020bsm}, FedLC~\cite{zhang2022fedlc} and
FedRS~\cite{li2021fedrs}. They test whether a correction of the loss alone repairs the long tail. They are applied
to GeFL-F without its generator.
\whennum{main/cifar10/FedAvg/bal}{\item \textbf{GeFL's baselines}: FedAvg~\cite{mcmahan2017fedavg}, FedProx~\cite{li2020fedprox} and
FedALA~\cite{zhang2023fedala} run within each architecture group, and AvgKD~\cite{afonin2022avgkd} distils across all
architectures, as GeFL compares them~\cite{kang2025gefl}. CCVR~\cite{luo2021ccvr} and FedETF~\cite{li2023fedetf}, two
long-tail methods, are applied within each group.}
\item \textbf{Model-heterogeneous methods from HtFLlib}~\cite{zhang2025htfllib}: prototypes (FedProto, FedTGP), a
generator of embeddings (FedGen), a shared global head (FedGH), shared last layers (LG-FedAvg) and shared
sub-networks (FedMRL). They represent the other ways in which clients with different models exchange knowledge.
\item \textbf{References}: Local, in which each client trains its extractor and head alone, is the reference without
federation.\whennum{main/cifar100/Centralised (pooled data)/bal}{ The pooled-data reference trains the same
architectures with cross-entropy on all training data pooled, without a generator and without a long-tail
correction.}
\end{itemize}
Methods designed for one shared model (\cref{tab:baselines}, lower part) are compared in the one-shared-model setting
only.

\paragraph{Settings and tuning} No baseline was tuned on our data; their settings come from different sources:
\begin{itemize}
\item the HtFLlib methods use the values of HtFLlib's run scripts, with 5 local epochs per round to match Stage III
(\cref{app:protocol});
\item the LongTailLib methods use the benchmark's common settings, which differ from some methods' own papers;
\whennum{main/cifar10/FedAvg/bal}{\item the grouped baselines use the settings of GeFL's code (FedAvg, FedProx with $\mu=0.01$, AvgKD) and of the
authors' code (FedALA) or LongTailLib (CCVR, FedETF);}
\item Balanced Softmax and FedLC ($\tau=1$) are re-implemented losses with the client's add-one smoothed class
counts, and FedRS ($\alpha=0.5$) with the classes the client lacks;
\item FedDF uses 20 server distillation steps per round (\cref{app:protocol}).
\end{itemize}
The settings of \ours (\cref{tab:hyper}) were fixed during its development, on earlier runs of the same benchmarks
with seeds 0 to 5. These included seeds 3 to 5 with the same client splits as the reported runs, and every earlier
run was evaluated on the same test sets. The development compared about 36 configurations of the method and its
variants on CIFAR-10-LT and 17 on CIFAR-100-LT (listed in the experiment ledger of the released code), and runs on MNIST, Fashion-MNIST and
SVHN; it never used the datasets with natural class imbalance. The settings were not changed for the runs
reported here (\cref{sec:setup-threats}).

\subsection{Metrics}\label{sec:setup-metrics}

Let $r_{gc}$ be the recall of class $c$ by the model of architecture $g$ on the official test set. The test set is
balanced on CIFAR-10\whennum{main/fmnist/FedECS-LT/bal}{, Fashion-MNIST} and CIFAR-100 and imbalanced on the naturally imbalanced
datasets\whennum{main/mnist/FedECS-LT/bal}{, MNIST}\whennum{main/svhn/FedECS-LT/bal}{, SVHN}; balanced accuracy weights every class equally in either case. The primary metric is the balanced accuracy, $\frac1G\sum_g\frac1C\sum_c r_{gc}$: the mean
over the $G=10$ client models of each model's mean class recall. GeFL~\cite{kang2025gefl} also averages over the
ten models, with top-1 accuracy at each model's best round. It is reported for every method without the readout (\ours with its readout, and its heads only)
and, for the methods of the GeFL-F pipeline, also with the readout added; the second set answers RQ3.

The other metrics are:
\begin{itemize}
\item the recall of the tail classes, the last 40\% by frequency rank, and of the worst class,
$\min_c\frac1G\sum_g r_{gc}$, the lowest class recall after averaging recall over the models;
\item the number of classes with zero recall for every model;
\item the expected calibration error with 15 bins~\cite{guo2017calibration};
\item the balanced accuracy of the weakest architecture;
\item the accuracy on each client's own class mix: the test accuracy re-weighted to the class frequencies of that
model's clients.
\end{itemize}
Every per-class metric is logged for every class at every evaluation; \cref{app:more} defines the secondary
metrics of its per-dataset tables.

GeFL's code reports each model's best test accuracy over the evaluated rounds. We report the model after the last
round, which involves no selection on the test set. GeFL's measure is given in \cref{tab:app-gefl}.

Cost is the communication per client, the wall-clock time of a run and the floating-point operations
(\cref{app:protocol}). The times were measured on a T4 GPU that in most notebooks ran a second run at the same time,
so they are only indicative.

\subsection{Protocol and implementation}\label{sec:setup-impl}

Every configuration is run with seeds 3, 4 and 5; settings with fewer completed seeds say so. A seed fixes the
split and the initialisation of every method, so runs with the same seed are paired.

\ours and every method of the main setting run in Flower~\cite{beutel2020flower}. The one-shared-model baselines run
in the authors' LongTailLib code on the same client splits and are evaluated on the same test set. \Cref{app:protocol}
gives the software and hardware.

All releases of \ours use Flower's SecAgg+~\cite{bell2020secaggplus}, with 30-bit stochastic quantisation of every
vector after division by a public bound: a multiple of the federation size and of the largest value on the
validation features for the class and readout sums, and fixed bounds for the counts, the CCWA rows and the consensus
predictions. Values beyond eight times the bound would be clipped.

The Flower implementation was checked against our earlier implementation, which follows GeFL's code
(\cref{app:protocol}).

GPU computation is not bit-reproducible (cuDNN autotuning and non-deterministic GPU kernels), so two runs with the
same seed differ. A
notebook run twice with the same run list (\R{repeat/dataset}, \R{repeat/bal/n} runs) measures this. The
standard deviation of the difference between the two runs of one configuration is \R{repeat/bal/sd} points of
balanced accuracy as trained and \R{repeat/er/sd} with the exact readout.

\subsection{Statistical analysis}\label{sec:setup-stats}

We report the mean $\pm$ sample standard deviation over seeds. A difference to \ours is the mean paired difference
over the seeds both methods have, with a 95\% $t$ interval and the paired $t$-test. The $p$-values are corrected by
Holm's procedure~\cite{holm1979} over the other methods of the same table and setting: every method without the readout, and
the methods of the GeFL-F pipeline with the exact readout. Local is included; the pooled-data reference and the
diagnostic runs and the heads of \ours alone are not. There is no correction across datasets or metrics.
``Best'' and ``strongest other method'' are decided on the seeds both methods have.

With three seeds the tests have little power, and they assume normally distributed paired differences: a sign-flip permutation test cannot
give $p<0.25$ with three paired differences. A test result near $p=0.05$ can also depend on which methods form the Holm
family. GPU non-determinism alone gives the mean of three paired differences a standard deviation of about half the
two-run value above; we treat differences smaller than twice that, \R{repeat/bal/floor} points as trained and
\R{repeat/er/floor} with the exact readout, as unresolved. Exceeding the floor is necessary, not sufficient: a
difference above it is resolved only if its paired test is also significant after Holm's correction.

\subsection{Threats to validity}\label{sec:setup-threats}

\paragraph{Internal validity}
\begin{itemize}
\item \textbf{Tuning.} The settings of \ours were fixed during its development on the same benchmarks, partly with
the same seeds and client splits and on the same official test sets (\cref{sec:setup-methods}), while the baselines
were not tuned. The reported numbers may therefore favour \ours.
\numelse{fresh/cifar100/margin}{Seeds 6--8, never used before, check the main comparison on new client splits
(\cref{sec:res-main}).}{There are no client splits that the development never saw.}
\item \textbf{Compute.} \ours trains its heads for ten synthetic epochs per round, against one for GeFL-F and FedDF
and none for the methods without a generator (\cref{tab:fairness}), and it communicates more (\cref{tab:cost}); the
methods were not compared at matched communication or wall-clock time.
\numelse{comp/cifar10/largest}{The ablation with one synthetic epoch (\cref{tab:components}) shows how much of the
result of \ours depends on the longer phase.}{How much of the result of \ours depends on the longer phase is not
measured: the ablation with one synthetic epoch is not part of the results reported here.}
\numelse{abl/cifar10/heads_vs/GeFL-F (T_s=10)}{GeFL-F and FedDF were also run with ten synthetic epochs
(\cref{sec:res-ablation}).}{What GeFL-F or FedDF would reach with ten synthetic epochs is not measured either.}
\item \textbf{Missing runs.} \claim{Some settings have fewer than three completed seeds; their tables say so, and a
value from one seed has no interval.} With one shared model, runs of \ours failed on some seeds and imbalance ratios
where the baselines finished, so the missing runs are not random; \cref{tab:shared} gives the seeds that completed.
\item \textbf{Ports.} The HtFLlib methods were designed for end-to-end training and run here on a frozen extractor
with HtFLlib's settings. \Cref{sec:res-main} shows that FedProto and FedTGP lose accuracy after their first evaluated
rounds, which may mean that these settings do not suit frozen features.
\item \textbf{Non-determinism.} Pairing by seed removes the variation of the split but not that of GPU computation
(\cref{sec:setup-impl}).
\end{itemize}

\paragraph{Construct validity}
\begin{itemize}
\item Balanced accuracy is a mean over ten models of different sizes, so a large gain of the small heads and a small
gain of the large heads give the same number. \Cref{tab:app-worstarch} gives the weakest architecture.
\item The readout was added to the methods of the GeFL-F pipeline but not to the HtFLlib methods, so the margins of
\ours over the latter include the readout's gain. The readout is the same linear classifier for every body, so
accuracy with it does not measure every property of a representation.
\item The server holds a small validation set (held out from the training data) for the generator diagnostics and
the secure-aggregation bounds; a deployment without such data would need another source for the bounds.
\item The last-round model can be below a method's best round; \cref{tab:app-gefl} gives the best round.
\end{itemize}

\paragraph{External validity}
\begin{itemize}
\item The long tail is synthetic on the benchmarks, with the same tail classes in every run.
\item The limits of the study's scope (a small frozen extractor, label shift only, one client per architecture) are
listed in \cref{sec:discussion}.
\end{itemize}
