Class-Balanced GeFL‑F Frequency-weighted aggregation and fidelity-gated sampling for model-heterogeneous federated learning on long-tailed data

GeFL‑F lets clients with different neural architectures collaborate by sharing a feature-generative model instead of a common target network. It assumes, silently, that every class is equally learnable. Under long-tailed data that assumption breaks: in our measurements, tail-class accuracy collapses to 0.4% while head classes hold at 43%. This document sets out the two mechanisms we propose, the mathematics behind them, our experimental design, the preliminary evidence, and five fallback directions.

01Problem statement

Two conditions that co-occur in every realistic deployment, which no existing method handles together.

Federated learning trains a model across clients that cannot pool their raw data. Two conditions hold simultaneously in almost any real deployment, and the literature treats them separately.

Model heterogeneity. Clients run different architectures. A district hospital with one GPU cannot run the network a research hospital runs; a phone cannot run what a workstation runs. Classical FedAvg requires every client to hold the same parameter vector, so it simply does not apply.

Class imbalance. The label distribution is long-tailed both globally and per client. Rare diseases are rare everywhere; manufacturing defects are, by definition, the minority class. No two clients see the same case mix.

GeFL‑F [1] solves the first condition elegantly. Rather than sharing a target network, clients share a common feature extractor and a feature-generative model trained on the extractor's output. Synthetic features carry global knowledge between architecturally incompatible clients. The target networks themselves — the heterogeneous "headers" — never need to agree on a shape.

But GeFL‑F is class-blind at both of its coordination points:

wg  ←  1|𝒞|  Σk ∈ 𝒞  wk          yi  ∼  Uniform{1,…,C}
(1)

The left rule averages every client's generator update with identical weight, whatever class distribution that client actually holds. The right rule draws the conditioning label for every synthetic feature uniformly, regardless of whether the generator can render that class yet. Neither expression contains a single term derived from class frequency or class-conditional generator quality.

Measured consequence

On CIFAR‑10‑LT at imbalance factor 0.01, our reproduction of vanilla GeFL reaches 43.3% accuracy on head classes and 0.4% on tail classes. The framework is not mildly degraded on rare classes — it has effectively stopped predicting them. Section 11 gives the full table.

02Objectives and research questions

What we will have demonstrated, and the questions each experiment answers.

Objectives

  1. O1 — Quantify the gap. Measure, per class-frequency bucket, how much accuracy GeFL and GeFL‑F lose under long-tailed data. This is not reported anywhere in the base paper.
  2. O2 — Correct the aggregation rule. Design and validate a class-frequency-aware replacement for the flat average of the generator's conditioning pathway.
  3. O3 — Correct the sampling rule. Design and validate a schedule for the conditioning-label distribution that is gated on per-class generator reliability.
  4. O4 — Preserve the base guarantees. Show the modifications do not degrade overall accuracy, do not worsen memorization as measured by MND, and do not increase communication cost.
  5. O5 — Establish generality. Demonstrate the mechanisms transfer across four datasets, three feature-generator families (CVAE‑F, DCGAN‑F, DDPM‑F), and client populations from 10 to 100.

04How GeFL and GeFL‑F actually work

The base framework, component by component, at the level of detail a whiteboard derivation requires.

4.1 The core idea

Ordinary FL averages target networks. That requires architectural agreement. GeFL breaks the dependency by averaging a generator instead. Every client can train the same small conditional generator regardless of what target network it runs; the generator's samples then act as a shared, architecture-neutral teaching signal.

GeFL‑F refines this. Instead of generating images, it generates intermediate features — the output of a small shared feature extractor. Features are lower-dimensional than images, so the generator is smaller, cheaper to communicate, and — as the base paper demonstrates via the MND metric — substantially less prone to memorizing training samples.

4.2 Model decomposition

Each client's target network splits into two pieces:

θm  =  { θf,   θhm }      where   θf is shared by all clients,   θhm is shared only within architecture group m
(2)

In our implementation the feature extractor is a single block — Conv2d(in, 32, 3×3) → BatchNorm2d → ReLU → MaxPool2d(2) — so a 32×32 CIFAR image becomes a 32×16×16 feature tensor. All discriminative capacity lives in the header, which is where architectural heterogeneity is expressed. We use three header families: header_small (2 conv blocks), header_deep (4 conv layers with a residual skip), and header_wide (2 wide conv blocks with BatchNorm).

4.3 The three stages

Stage i · TFE rounds
Warm up the feature extractor

Clients train θf and their own θh jointly on real local data. The server averages θf across all clients and θhm within each architecture group.

θfg ← Agg({θfk}k∈𝒞)
Stage ii · TKA rounds
Train the feature generator

F is now frozen. Each client passes real data through F, obtains features, and trains GF on the (feature, label) pairs. The server averages generator weights.

xi ← F(xi);  wk ← wk − β∇JG
Stage iii · TTN rounds
Train the headers

F stays frozen. Each round each client trains its header for Ts epochs on synthetic features from GF, then Tr epochs on real features from F. Grouped averaging.

(xfeat, y) ∼ GF(z|y, wg)

Two details matter for our derivation and are easy to get wrong on the whiteboard. First, the synthetic and real phases are sequential, not mixed — they never share a batch, and the reference implementation constructs a fresh optimizer for each phase. Second, the ratio Tr/Ts = 5 means real data gets five times the epoch exposure synthetic data gets, which is what keeps the headers anchored when generator quality is poor.

05Where the framework breaks under a long tail

A formal account of both failure modes — including one correction to our own earlier framing.

5.1 Failure mode one: the conditioning row is voted on by clients with no evidence

Every conditional generator separates a conditioning pathway from an unconditional trunk. In our CVAE the pathway is an nn.Embedding of shape (C, d): row r holds the learned representation of class r. The trunk is every convolution in the encoder and decoder.

Under the flat average of line ①, row r of the global embedding is

wcond, rg  =  1|𝒞|  Σk ∈ 𝒞  wcond, rk        — independent of nk,r
(3)

Consider a client k with nk,r = 0 — it holds no samples at all of class r. Its local row wcond,rk received no gradient signal for class r during local training; it is whatever the broadcast global value was, plus whatever drift the shared trunk induced. Yet Equation 3 gives it exactly the same 1/|𝒞| vote as a client holding 500 samples of class r.

With C classes and a long tail, most classes are held by a small minority of clients. The informative minority is therefore systematically outvoted by an uninformed majority, and the severity scales with imbalance. This is the precise sense in which GeFL‑F is class-blind at aggregation.

5.2 Failure mode two: sampling is fidelity-blind, not frequency-blind

Correction to a common framing — be ready for this question

It is tempting to say "uniform sampling ignores class imbalance." That statement is wrong, and a careful reader will catch it. Uniform sampling over C classes assigns each class probability 1/C. Under a long tail where the natural frequency of a tail class is πc = 0.005, uniform sampling gives it 0.1 — a twenty-fold over-representation relative to nature. Uniform sampling is already an aggressive rebalancing scheme.

The real defect is different, and sharper: uniform sampling is fidelity-blind. It requests the generator to render a tail class at exactly the same rate as a head class, at every point in training — including early rounds when the generator has seen almost no examples of that class and produces something closer to noise. Those malformed samples arrive labelled with high confidence, and the header trains on them. For precisely the classes with too little real data to correct the error, we inject the most label noise.

Formally: let qc(t) denote the fidelity of the generator on class c at round t — the probability that a sample drawn as class c is in fact recognisable as class c. The expected useful signal contributed by the synthetic phase is

𝔼[useful]  =  Σc  p(y=c) · qc(t)       𝔼[noise]  =  Σc  p(y=c) · (1 − qc(t))
(4)

Uniform p(y) maximises neither. It is a fixed policy applied to a quantity, qc(t), that varies by two orders of magnitude across classes and changes by an order of magnitude over training. Any fixed policy — uniform, natural-frequency, or static inverse-frequency — is dominated by one that observes qc(t) and adapts.

This reframing is important for how we position the contribution. Mechanism B is not a rebalancing scheme; it is a curriculum. Early in training it samples tail classes less than uniform does, because the generator cannot render them. Late in training it samples them more than uniform does, because by then it can.

06Mechanism A — frequency-weighted conditioning aggregation

Replace one line of the server's aggregation rule. Nothing else in the framework changes.

6.1 Parameter partition

Each registered generator declares which of its state_dict keys constitute the conditioning pathway, via a method conditioning_parameter_names(). For our CVAE this returns ["label_embed.weight"]; for the conditional DDPM it returns the class embedding including the null token used for classifier-free guidance. Everything else is trunk.

w  =  wtrunk  ∪  wcond,     wcond ∈ ℝC×d     (row r ↔ class r)
(5)

6.2 The trunk keeps volume weighting

The trunk encodes class-agnostic structure — edges, textures, the shape of the feature manifold. A client with more data has seen more of that structure regardless of which classes it holds, so standard volume-weighted FedAvg is the right rule and we keep it:

wtrunkg  ←  Σk ∈ 𝒞  nkΣj nj   wtrunkk
(6)

6.3 Each conditioning row gets its own weighting

Row r should be determined by the clients that actually hold class r. We weight by the effective number of samples of Cui et al. [2], which grows monotonically with count but saturates — the hundredth sample of a class informs less than the tenth:

E(n)  =  1 − βEN n1 − βEN       a(r)k  =  E(nk,r)Σj ∈ 𝒞 E(nj,r)       wcond, rg  ←  Σk  a(r)k · wcond, rk
(7)

Three properties fall out immediately, and all three are worth stating aloud in a review:

  • E(0) = 0. A client holding zero samples of class r receives exactly zero weight on class r's row. The uninformed-majority problem of §5.1 disappears by construction.
  • Weights sum to one per row. The update remains a convex combination, so it cannot inflate the parameter norm — the standard stability argument for FedAvg carries over unchanged.
  • βEN → 0 recovers uniform-over-holders; βEN → 1 recovers proportional-to-count. The hyperparameter interpolates between two sane extremes, which is why a sensitivity sweep over it is meaningful rather than arbitrary.
The direction question — expect to be challenged here

Cui et al. use 1/E(n) as a loss weight: rare classes get more loss weight. We use E(n) directly as an aggregation weight: clients holding more of a class get more say over that class's row. These point in opposite directions, and that is correct, because they answer different questions.

Cui's question is "how much should this example influence the loss?" — answer: rare examples more, to counteract their scarcity. Our question is "how much should this client's estimate of class r influence the global estimate of class r?" — answer: the client with more evidence about class r, more. Inverting our direction would hand the class-r row to the clients that have never seen class r, which is incoherent.

We nonetheless run the inverted variant as an ablation row (RQ2), because asserting this without measuring it is exactly the kind of claim a reviewer should not accept on argument alone.

07Mechanism B — fidelity-gated sampling curriculum

Replace the conditioning-label distribution with one that observes generator reliability and adapts.

7.1 Obtaining a per-class fidelity signal for free

During the synthetic phase of stage (iii), the header already performs a forward pass on every synthetic feature to compute cross-entropy. The softmax output of that same pass gives us confidence at no additional cost. For a batch of synthetic features drawn as class c:

p̄c(t)  =  1|Bc|  Σi ∈ Bc  ρ( Tθʰ( xfeati ) )c       fc(t)  ←  λ fc(t−1) + (1−λ) p̄c(t)
(8)

where ρ is softmax and Bc is the subset of the batch drawn as class c. The EMA with decay λ = 0.6 smooths the estimate across rounds. Fidelity is accumulated across the whole synthetic phase and applied once at its end — not per batch, which would make the estimate track within-epoch noise.

7.2 The sampling distribution

Define the global gate g = (1/C)Σc fc, the mean fidelity across classes. The target distribution blends the natural frequency with an inverse-frequency term that is itself scaled per class by that class's own fidelity:

pinvc  =  (πc−1)γ · fcΣc′ (πc′−1)γ · fc′        p(y = c)  =  (1 − g) πc  +  g pinvc
(9)

The design has two nested gates, and articulating both is the clearest way to defend it:

  • The global gate g controls when rebalancing switches on. Early in training every fc is low, so g ≈ 0 and p ≈ π — we sample near the natural distribution and simply do not ask the generator for classes it cannot produce.
  • The per-class factor fc inside pinv controls which rare classes get promoted. A class that is rare and still badly modelled does not get oversampled merely for being rare — the very failure that a naive inverse-frequency scheme would produce.

7.3 Why this is a curriculum, not a reweighting

Section 5.2 established that uniform sampling already over-represents the tail. Mechanism B's trajectory is therefore non-monotonic relative to the baseline: it starts below uniform for tail classes and ends above it. The worked numbers in §9.2 make this concrete. The claim we will defend is not "we rebalance and GeFL‑F does not" — it is "we spend synthetic budget on a class only once that budget buys signal rather than noise."

10.2 Baselines

  • FedAvg (grouped) — clients partitioned by architecture, FedAvg run within each group. The base paper's own convention.
  • FedProx — proximal term against client drift.
  • Vanilla GeFL‑F — the direct precedent; flat aggregation, uniform sampling. LG‑FedAvg is also included, since it shares a feature extractor without the generator and therefore isolates the generator's contribution.
  • CReFF-style classifier retraining [3] — the strongest classifier-side long-tail method that can be adapted to this setting. Tests whether a generator-side fix is complementary to, or merely a restatement of, a classifier-side one.
  • Static inverse-frequency sampling — Mechanism B with the gate held at g = 1. Isolates the curriculum from the rebalancing.

10.3 Metrics

  • Overall accuracy, averaged across all heterogeneous target networks — comparable to the base paper's Table II.
  • Bucketed accuracy — head / medium / tail by class frequency tercile. This is the headline metric and is not reported in the base paper at all.
  • Macro‑F1 and class-balanced accuracy — imbalance-aware aggregate measures.
  • Generator label accuracy — fraction of synthetic samples a trained probe assigns to their conditioning label. Distinguishes "the classifier got better" from "the generator got better," which is the mechanistic claim.
  • MND ratio [1] — memorization proxy via LPIPS nearest-neighbour distances. Values > 1 indicate memorization risk.
  • Communication and compute — parameters transmitted per round and MACs, following the base paper's Tables V and VI.

10.4 Infrastructure

All runs execute on Kaggle 2×T4 in headless "Save & Run All" mode, two configurations in parallel via CUDA_VISIBLE_DEVICES. The sweep harness is idempotent — each run writes its own CSV and completed runs are skipped on re-execution — so a sweep exceeding Kaggle's 12-hour session cap resumes cleanly. Every reported number is traceable to a git commit hash, and the code is released alongside the paper.

What we have measured so far, stated with the caveats it deserves.

Two caveats, both important

Statistical. The numbers below are from a single seed at half the paper's round budget (50 + 50 instead of 100 + 100). They are a decision gate, not a result. Nothing here is publishable as it stands.

Framework. Table 11.2 was measured on GeFL, the image-space sibling, because it was the faster framework to iterate on while the implementation was being corrected. Our target is GeFL‑F. Replicating it on GeFL‑F is the immediate next milestone and the first entry in the week 3–4 sweep.

11.1 Baseline reproduction

Before measuring anything we verified the implementation against the base paper. On balanced MNIST, our GeFL reproduction reaches 93.76% overall accuracy with an MND ratio of 0.625. The paper reports 94.46 ± 0.43% for FedCVAE on MNIST with ten architectures; we use three and a shorter schedule, so landing slightly below is expected. The MND value being well under 1 matches the paper's reported 0.714 for the same configuration. We treat the reproduction as sound.

Reaching that point required fixing six defects in our earlier implementation, of which the most consequential was a VAE loss using reduction="mean" with a 0.1 KL weight instead of the sum-reduction ELBO the reference uses. That single error under-weighted the KL term by roughly the pixel count and produced a materially different generator.

12Privacy analysis

Mechanism A requires clients to upload class histograms. We treat that as a first-class concern, not a footnote.

To compute a(r)k the server must know nk,r for every client and class. This is a genuine increase in disclosure over vanilla GeFL‑F and we will not present it otherwise.

12.1 Situating the leak

Context
It extends an existing disclosure rather than creating a new one

Volume-weighted FedAvg already requires nk. We extend a scalar to a C-vector. The kind of information is unchanged — dataset composition metadata — while the dimension rises from 1 to C.

Context
It is small relative to what is already transmitted

Clients already upload full generator weights each round, which the base paper's own MND analysis shows can memorize training samples. A histogram is a far weaker signal than a generator that has fit the data it summarises.

Honest limitation
Every method in this literature has the same requirement

CReFF, Ratio Loss, BalanceFL, FedCBA and FedSat all need class-distribution knowledge server-side. This is a category-wide trade-off. That does not excuse it — it means our threat model must be stated explicitly rather than assumed.

Honest limitation
Under a stronger threat model it needs a defence

For an adversarial server in a regulated deployment, raw histograms are not acceptable. The mitigations below compose with our method; we will implement at least the first as an ablation.

12.2 Mitigations, in order of cost

  1. Differentially private counts. Upload ñk,r = nk,r + Lap(1/ε). Aggregation still works with noisier weights. We will run this as an ablation column reporting accuracy against ε ∈ {0.1, 1, 10}, which turns a limitation into a result.
  2. Coarse buckets. Clients report a head/medium/tail label per class rather than an exact count. Weaker signal, weaker leak.
  3. Secure aggregation. The server observes only the aggregated numerator Σk E(nk,r)·wcond,rk and denominator, never individual histograms. Correct but protocol-heavy; we scope it as future work.

We will also report MND for every configuration. If the memorization ratio stays well below 1 — as our 0.625 reproduction suggests — then the histogram becomes the dominant residual privacy risk, and quantifying it under DP is the right response.

13Five fallback directions

Each has a stated trigger, a mechanism, and an honest assessment of what it costs and what could go wrong.

The primary direction has cleared its decision gate, but a single-seed gate is weak evidence. Each fallback below is specified to the same depth as the primary mechanism: where it attaches to the GeFL‑F pipeline, its full mathematical form, what it changes architecturally, and what could go wrong. All five reuse the identical experimental harness, datasets, baselines and metrics — only the mechanism changes, so switching costs days rather than weeks.

The problem it solves

Mechanism A weights a client's vote on class r by how much of class r it holds. It does not ask whether that client's generator actually learned class r. A client with 40 samples of a class but a diverged local generator gets more weight than a client with 20 samples and a well-fitted one. Quantity is a proxy for quality, and under extreme imbalance it is a weak one.

There is a second, sharper motivation. Our current fidelity signal for Mechanism B is partially circular: the header scores synthetic samples it is simultaneously training on, so confidence rises with training whether or not the generator improved. F1 replaces that signal with one that cannot be gamed, and reuses it for aggregation too.

Formulation

Let 𝒟k = 𝒟traink ∪ 𝒟holdk with the holdout roughly 10%. Client k's quality on class r is

qk,r  =  exp −  1|𝒟holdk,r|  Σx ∈ 𝒟holdk,r  ‖ F(x) − G₌(z | r, wk) ‖22    ∈ (0, 1]
(13)

and the aggregation weight becomes a product of evidence and demonstrated quality:

a(r)k  =  E(nk,r) · qk,r Σj E(nj,r) · qj,r      — Mechanism A is the special case q ≡ 1
(14)
Why it is a genuine contribution, not a patch

Framed this way, F1 is arguably a stronger paper than the primary proposal. "Weight each client's contribution to a class by how well that client actually modelled the class" is a general principle for federated generative models, not a long-tail-specific trick. It would apply to any FedGen-family method. If Mechanism A underperforms, promoting F1 to the headline contribution is a defensible pivot rather than a retreat.

Risks
  • Holding out 10% of an already-tiny tail-class sample may leave zero holdout examples for the rarest classes. Mitigation: fall back to qk,r = 1 (pure Mechanism A) when the holdout for class r is empty, which is exactly the well-defined degenerate case.
  • Reconstruction error is a poor quality proxy for GANs, which have no encoder. For DCGAN‑F we would use the discriminator's score on held-out real features instead — a natural analogue.

The principle

Kang et al. [4] established one of the most robust results in long-tailed recognition: when a network trains on imbalanced data, the learned representation is largely fine, and almost all of the damage is concentrated in the final classifier's decision boundaries and weight norms. Head-class weight vectors grow large, tail-class vectors stay small, and the argmax is biased before the features are even considered.

The prescribed fix is to decouple: train the representation on the natural imbalanced distribution, then freeze it and retrain only the classifier on a class-balanced sample. In ordinary federated learning this is hard, because no client can construct a class-balanced batch of a class it does not hold. GeFL‑F removes that obstacle entirely — the feature generator can synthesise as many features of any class as required, on demand, at any client.

Formulation

Write the header as θhm = {ψm, Wm} — convolutional body ψ and final linear classifier W ∈ ℝC×d. Stage iv freezes ψ, reinitialises W, and minimises

minW   1C  Σc=1C   1N/C  Σi=1N/C   CE( W · ψm( G₌(zi | c, wg) ),   c )
(15)

The outer average over classes with exactly N/C samples each is what makes it balanced — no reweighting term is needed because the data is balanced rather than the loss.

Honest assessment

This is the lowest-novelty and highest-certainty fallback. It transplants a well-known centralized technique into a federated feature-generative setting. On its own that is a workshop paper, not a conference paper. Its value is threefold: it will almost certainly produce a positive result; it composes with everything else so it can be an additional contribution rather than a substitute; and it makes a specific, defensible claim about GeFL‑F — that the feature generator uniquely enables a correction that ordinary federated learning cannot perform.

The problem it solves

A conditional VAE draws every sample, for every class, from one shared prior z ∼ 𝒩(0, I). The decoder must partition that single Gaussian ball into C class regions. Training pressure is proportional to sample count, so head classes claim most of the volume and tail classes are squeezed into slivers — or overlap head regions entirely, which is exactly what produces a synthetic "tail" sample that looks like a head class wearing the wrong label.

Mechanisms A and B cannot fix this. A changes who decides the conditioning row; B changes how often we ask for a class. Neither gives the tail more room to exist in.

Formulation

Replace the fixed prior with per-class parameters {μc, σc}, learned jointly and aggregated as part of the conditioning pathway. The ELBO becomes

ℒc  =  𝔼q(z|x,c)[ log p(x | z, c) ]  −  DKL( q(z | x, c) ‖ 𝒩(μc, diag σc2) )
(16)

with the shrinkage that keeps scarce classes honest:

μ̂c  =  κc · μc,      κc  =  ncnc + τ0      — nc → 0 gives μ̂ → 0; nc ≫ τ0 gives μ̂ → μ
(17)

This is a standard empirical-Bayes construction: a class with abundant data is trusted to place its own mean; a class with two samples is pulled back toward the shared origin, recovering the current behaviour in the limit. τ0 is a single new hyperparameter with a clear interpretation — the sample count at which a class is trusted halfway.

Risks
  • Overfitting the priors. A class with 2 samples estimating a d-dimensional mean is badly under-determined. Equation 17 is the mitigation and its behaviour at both limits is provably sane, which is why we would present the shrinkage as part of the contribution rather than as a hack.
  • Architecture change forces re-running baselines. Every comparison number would need regeneration, which is the main reason this sits third rather than first.
  • Does not transfer to GANs. DCGAN‑F has no explicit prior to reshape in the same way, so this fallback would narrow the paper to VAE‑F and DDPM‑F. That is a real scope cost.

The problem it solves

There is an intermediate failure mode between "the generator works" and "the generator is broken": synthetic tail features that are recognisable but sit slightly off the real feature manifold. Training on them teaches the header a decision boundary calibrated to a distribution that test data will never come from. Neither A nor B helps — A improves who decides the conditioning, B decides when to sample, but if the sample itself is displaced, both mechanisms faithfully deliver a displaced sample.

The fix is to never train on a purely synthetic feature. Interpolate every synthetic tail feature toward a real feature of the same class that the client actually holds. The result inherits the diversity of the synthetic sample and the manifold-correctness of the real one.

Formulation
δ ∼ Beta(a, a),    xrealc ∼ Uniform(𝒟k,c),    xsync ∼ G₌(z | c, wg)
x̃ = δ · F(xrealc) + (1 − δ) · xsync,    loss = CE( Hm(x̃),  c )
(18)

Note the label is not mixed. Standard mixup interpolates labels because it mixes across classes; here both endpoints are class c, so the label is unambiguous. This is closer to SMOTE than to mixup in spirit, executed in a learned feature space with a generative model supplying one endpoint. When 𝒟k,c = ∅ — the client holds no real sample of class c — we fall back to δ = 0, i.e. current behaviour.

Positioning against GAMO

GAMO [5] performs classifier-guided generative oversampling of minority classes in a centralized setting, generating minority points as convex combinations of existing ones under adversarial guidance. F4 is recognisably in that lineage, and we would say so explicitly rather than obscure it. The differences that make it a contribution: it is federated, so no party sees the full minority distribution; it operates in a shared learned feature space rather than input space; and one endpoint comes from a federated generative model carrying global knowledge rather than from the local minority set. "Federated GAMO in feature space" is an honest and quite strong framing.

The principle

Under a long tail the training prior πc differs from the balanced test prior 1/C. A softmax classifier trained by ordinary cross-entropy learns ptrain(c | x), but the quantity we want at test time is ptest(c | x). Bayes' rule relates them exactly, and the correction is a per-class additive constant in logit space — no retraining, no extra parameters, no approximation.

Formulation

Post-hoc form, applied at inference with no retraining:

ŷ  =  arg maxc   [  Hm(x)c  −  τ · log πc  ]
(19)

Or the training-time form (balanced softmax), which is usually slightly stronger:

ℒ  =  − log exp( Hm(x)y + τ log πy ) Σc exp( Hm(x)c + τ log πc )
(20)

τ = 1 is the theoretically exact correction under pure label shift; treating τ as a tunable in [0, 1.5] usually helps because the shift is not purely in the prior.

Why this is really a threat assessment
Run this in week 5 regardless of whether the primary works

F5 is two days of work and is near-guaranteed to improve tail accuracy. That makes it the most dangerous baseline in the paper, and we would rather discover its strength ourselves than have a reviewer discover it for us. Three outcomes, all of which we can act on:

  • A+B beats F5. Strong result — we address something a classifier-side correction cannot.
  • A+B stacks on top of F5. The best outcome — evidence the mechanisms fix the generator while F5 fixes the boundary, two distinct problems. This becomes the headline.
  • F5 alone matches A+B. Our contribution is weak as framed. We would pivot the paper toward the diagnosis — showing that GeFL‑F's tail failure is a boundary problem rather than a generative one, which is itself a publishable finding about the framework.
Summary of the contingency posture

Five mechanisms, two on the generator side and two on the classifier side with one hybrid, all attaching to the same pipeline and all reusing the same harness. Four of the five compose with the primary proposal rather than replacing it. The branch decision is made from a metric we already log. Under any outcome, including total failure of Mechanisms A and B, the project produces a measured, defensible account of why GeFL‑F fails on rare classes and what does or does not repair it.

15Defence brief

Anticipated questions with answers, written so anyone on the team can field them.

In one sentence, what is the contribution?

GeFL‑F coordinates heterogeneous clients through a shared feature generator, but both of its coordination rules — how generator updates are averaged, and how synthetic labels are drawn — ignore class frequency and class-conditional generator quality entirely; we make both rules class-aware and show it recovers tail-class accuracy that the framework otherwise loses almost completely.

Why work on GeFL‑F rather than GeFL?

Three reasons, in order of weight:

  • GeFL‑F is the better framework by the base paper's own evidence — more robust as client count grows, lower communication and compute cost, and substantially better MND privacy numbers (0.108 versus 0.714 for CVAE).
  • Feature space is where the class-imbalance problem is more tractable: features are lower-dimensional, so a generator can model a rare class from fewer samples than it would need in pixel space.
  • It is the version a practitioner would actually deploy, so improving it is the more useful contribution.

We work on GeFL‑F exclusively. Our earliest mechanism-validation runs used GeFL because it was faster to iterate on while the implementation was being corrected, and those numbers appear in §11.2 labelled as such. They are evidence that the mechanisms function, not GeFL‑F results. Every experiment from this point forward targets GeFL‑F.

Doesn't uploading class histograms break privacy?

It is a real increase in disclosure and we do not minimise it. Four points, and Section 12 has the full treatment:

  • Volume-weighted FedAvg already requires the total count nk. We extend a scalar to a C-vector — the same kind of metadata at higher dimension.
  • Clients already upload full generator weights, which the base paper's MND analysis shows can memorize training samples. A histogram is a far weaker signal than a model fitted to the data it summarises.
  • Every class-imbalance FL method has this requirement — CReFF, Ratio Loss, BalanceFL, FedCBA, FedSat. It is a category-wide trade-off.
  • We will run a differentially private variant, adding Laplace noise to the counts, and report accuracy against the privacy budget ε. That turns the limitation into a measured result.
Why weight by effective number rather than its inverse, as Cui et al. do?

Because the two answer different questions. Cui asks "how much should this example influence the loss?" and answers "rare examples more," to counteract scarcity. We ask "how much should this client's estimate of class r influence the global estimate of class r?" and answer "the client with more evidence about class r, more."

The decisive case is a client holding zero samples of class r. Our direction gives it weight E(0) = 0. The inverted direction would give it the largest weight — handing the class-r conditioning row to clients that have never seen class r. That is incoherent. We nonetheless run the inverted variant as an ablation, because this argument should be supported by a measurement, not just asserted.

Isn't your fidelity signal circular? The header is training on the same samples it scores.

This is the sharpest criticism of the current design and the honest answer is: partially, yes. Header confidence rises over training whether or not the generator improves.

Two things bound the problem. The header also trains on real data for five times as many epochs, so it cannot drift arbitrarily toward trusting bad synthetic samples. And the signal is only used comparatively across classes within a round, not as an absolute quality measure — a uniform upward drift affects all classes and largely cancels in the normalisation of Equation 9.

That said, we do not consider the argument sufficient. Fallback F1 specifies three non-circular alternatives — held-out reconstruction error, a frozen referee classifier trained only on real data, and inter-client prediction agreement — and we will implement at least one as an ablation.

How is this different from FedGen or FedFTG?

FedGen and FedFTG both train a generator inside FL for knowledge transfer, so they are the closest related work and the paper engages them directly. Two differences:

  • FedGen trains its generator on the server from client label predictions and targets statistical heterogeneity, not model heterogeneity. FedFTG uses a generator for data-free distillation into a single global model. Neither operates in the fully model-heterogeneous setting where clients never share a target architecture.
  • Neither reasons about class balance at any point. Their aggregation and sampling rules are as class-blind as GeFL‑F's.

The contribution is not "use a generator in FL." It is "the aggregation and sampling rules of generator-mediated FL are class-blind, and making them class-aware measurably recovers tail accuracy."

Uniform sampling seems fine — every class gets equal share. Where is the problem?

This is the question we most want to be asked, because the naive framing of our own work gets it wrong. Uniform sampling is not frequency-blind in a harmful direction — at IF = 0.01 it over-samples the tail roughly twenty-fold relative to natural frequency. It is already aggressive rebalancing.

The defect is that it is fidelity-blind. It demands the generator render a tail class at the same rate as a head class in round 1, when the generator has seen almost no examples of it and returns noise carrying a confident label. Mechanism B is therefore a curriculum, not a rebalancing scheme: the worked example in §9.2 shows it sampling the rarest class at 0.113 early — below uniform's 0.250 — and 0.388 late, above it.

How do you know the generator improved, rather than just the classifier?

We log generator label accuracy — the fraction of synthetic samples that a probe assigns to their conditioning label — separately from downstream task accuracy. If Mechanism A works as claimed, generator label accuracy on tail classes should rise. If task accuracy rises while generator label accuracy does not, then something other than the stated mechanism is responsible and we need to find out what.

We also plan a t‑SNE visualisation of real versus synthetic feature distributions per frequency bucket, following the base paper's Figure 9.

How do you know the gate result is not just noise?

By accident, the gate sweep contains two pairs of identical runs. The “support floor” variant was meant to fall back to flat averaging for classes with fewer than 20 samples in a round, but the rarest class had 25, so the floor never activated. Those runs repeat A and A+B exactly, and they differ from the originals by at most 0.6 pp, against an effect of +8.2 pp overall and +4.2 pp tail.

That is evidence, not proof. The full sweep uses three seeds and a paired test. We also correct the record openly: an earlier draft called the floor a negative result, which it was not.

What is your statistical evidence?

Currently insufficient, and we will say so. Section 11 is a single seed at half the round budget — a decision gate, not a result. The full sweep runs three seeds per configuration and every headline number will be reported as mean ± standard deviation, with a paired t‑test against the baseline, matching the base paper's own convention.

What if none of it works?

Then we still have a paper, and it is a legitimate one. We would have measured and reported something nobody has published: how much class imbalance costs GeFL‑F, broken out by class frequency, together with the finding that the obvious corrections — frequency-weighted aggregation and adaptive sampling — do not fix it, and a diagnosis of why. Negative results with a clear mechanism are publishable, and Section 13's five fallbacks mean we would have four more mechanisms tested before reaching that conclusion.
