A question you will be asked

“Do you use data augmentation?” No. The reference GeFL implementation applies RandomCrop and RandomHorizontalFlip to CIFAR‑10; we deliberately do not, because the base paper isolates GeFL's contribution by evaluating without augmentation (their Table IV is the only augmented experiment). Adding it later is orthogonal and would lift every method roughly equally.

1.3 Long-tail construction — the exact schedule

μ = ρ1/(C−1),     nc = max( 1,  ⌊ Ncap · μc ⌋ ),    c = 0, 1, …, C−1

The number that explains everything downstream

Class 9 has 25 training images in the entire federation. Split across 10 clients under Dirichlet(0.3), a typical client holds two or three — and several clients hold zero. Every design decision in this project follows from that number. When the professor asks “why is this hard,” this is the answer: you are asking a federated generative model to learn a class from two examples per client, and then asking ten architecturally different networks to learn a decision boundary for it.

1.4 Frequency bucketing — and a subtlety

Classes are ranked by count and split into three buckets. The implementation is:

Bucket assignmentsampling/partition.py :: frequency_bucket_labels
ordered    = sorted(class_counts, key=lambda c: -class_counts[c])   # descending
per_bucket = max(1, C // num_buckets)          # 10 // 3 = 3
bucket(c)  = min(rank(c) // per_bucket, num_buckets - 1)

With C = 10 and 3 buckets, per_bucket = 3, so ranks 0–2 are head, 3–5 medium, 6–8 tail — and rank 9 hits the min(·, 2) clamp and also lands in tail. The tail bucket therefore contains four classes, not three.

Bucket composition — note the asymmetry
BucketClassesCountSamples% of pool

Tail accuracy is the unweighted mean over those four classes. A model that predicts nothing for class 9 but is perfect on 6, 7 and 8 would score 75% tail accuracy — worth knowing when interpreting the metric, and worth stating if asked how tail accuracy is computed.

1.5 The Dirichlet partition, step by step

The long-tailed pool is now split across K clients. The partition is done per class: for each class independently, a proportion vector is drawn from a Dirichlet and that class's samples are cut accordingly.

Partition algorithmsampling/partition.py :: dirichlet_partition
for attempt in range(50):                    # retry until no client is starved
    client_indices = {i: [] for i in range(K)}
    for c in range(C):
        idx_c = where(labels == c)              # all samples of class c
        shuffle(idx_c)
        p = rng.dirichlet(alpha=[α] * K)          # K proportions summing to 1
        cuts = (cumsum(p) * len(idx_c)).astype(int)[:-1]
        for i, chunk in enumerate(split(idx_c, cuts)):
            client_indices[i].extend(chunk)
    if min(len(v) for v in client_indices.values()) >= min_size: break
p(c) = (p(c)1, …, p(c)K) ∼ Dir(α, …, α),     nk,c ≈ p(c)k · nc
(4)
Effect of α · the concentration parameter controls cross-client skew
αBehaviourTypical draw for K=10
0.1Extreme skew — a class often lands almost entirely on one client(.87, .09, .02, .01, 0, …)
0.3Our default. Strong skew; most clients hold few or none of a given class(.41, .28, .13, .09, .05, .03, …)
1.0Moderate — flat Dirichlet, still uneven(.19, .16, .14, .12, .11, …)
∞Uniform — each client gets nc/K, i.e. IID(.10, .10, .10, …)
The compounding effect — explain this carefully

Class 9 has 25 samples globally. A Dirichlet(0.3) draw across 10 clients concentrates most of the mass on two or three clients. So a realistic outcome is: client A holds 9, client B holds 7, client C holds 4, clients D and E hold 2 and 3, and five clients hold zero.

Those five zero-holding clients are exactly the ones that, under GeFL‑F's flat averaging, still cast a full 1/10 vote on class 9's conditioning row. That is the mechanism our Mechanism A removes, and this is the concrete situation to draw on the board.

Implementation defect — raise this before the professor finds it

GeFL‑F's entire premise is that features are lower-dimensional than images, which is what makes the generator smaller and memorization weaker. Check our numbers:

Configurationfe_channelsFeature shapeDimensionsvs image (3072)
Reference implementation (paper)3(3, 16, 16)7680.25× — 4× smaller

Our feature tensor is 2.67× larger than the input image, not smaller. The reference sets output_channel = 3, img_size = 16 explicitly for every -F variant. With 32 channels we contradict the framework's stated motivation: the generator is not meaningfully smaller, and a 32-channel feature retains far more invertible information than a 3-channel one, which weakens the privacy argument that is GeFL‑F's main selling point over GeFL.

Action: add fe_channels = 3 as the paper-matched configuration and report both. This is a one-line config change, but every GeFL‑F number must be regenerated under it. It belongs in the ablation table as “feature dimensionality” — a legitimate axis the base paper itself studies under the name homogeneity level.

2.2 The three heterogeneous headers

All three consume the same (B, 32, 16, 16) feature tensor and emit (B, 10) logits. They differ in depth, width and topology — that difference is the model heterogeneity the framework exists to accommodate.

The reparameterization trick — why it is needed

We must sample z ∼ 𝒩(μ, σ²), but sampling is not differentiable. The trick moves the randomness outside the gradient path:

σ = exp(½ logσ²),    ε ∼ 𝒩(0, I),    z = μ + σ ⊙ ε     ∂z/∂μ = 1,   ∂z/∂σ = ε — both defined
(6)

Why Upsample + Conv instead of ConvTranspose2d

The reference uses ConvTranspose2d, which can only double a size exactly. We use nn.Upsample(size=…) followed by a stride-1 convolution, which hits an exact target size regardless of parity. That is what makes one class work for MNIST's 28px, CIFAR's 32px and STL‑10's 96px without per-resolution subclasses. It also avoids the checkerboard artifacts transposed convolutions are known for. This is a deliberate deviation and worth stating as such.

The loss — and the bug we fixed

ℒ = ‖x̂ − x‖²2  +  DKL( 𝒩(μ, σ²) ‖ 𝒩(0, I) )   =   Σi(x̂i−xi)²  −  ½Σj( 1 + logσ²j − μj² − σ²j )
(7)
Both terms use sum reduction — this was wrong until we fixed it

Our implementation previously used reduction="mean" with a 0.1 KL weight. Because reconstruction is summed over 32×16×16 = 8192 elements while KL is summed over 50 latent dimensions, mean-reduction plus a 0.1 weight under-weighted the KL term by roughly four orders of magnitude. The result was a near-autoencoder with an unregularized latent space, which samples badly. Restoring sum reduction was the single largest correctness fix in the project and is what took our MNIST reproduction to 93.76%.

Sampling

CVAE‑F generation — one forward pass, no iterationgenerators/ccvae.py :: sample
def sample(labels):              # labels: (B,) int64
    z = torch.randn(B, 50)        # (B, 50)   fresh Gaussian noise
    e = label_embed(labels)       # (B, 16)   learned per-class vector
    h = dec_fc(cat([z, e]))       # (B, 2048)
    h = h.view(-1, 128, 4, 4)
    x = decoder(h)                # (B, 32, 16, 16)
    return relu(x)

Cost: one forward pass. This is why CVAE‑F is the default — generating a batch of 128 synthetic features is as cheap as a single decoder evaluation.

Why the discriminator is federated too — a likely question

A GAN cannot be trained federated with only the generator shared. If each client kept a private discriminator, that discriminator would instantly overfit to its own local class distribution, and the generator would receive contradictory gradients from ten differently-biased critics — silently reintroducing exactly the class-imbalance pathology we are trying to remove. So CCGAN holds both G and D as sub-modules and the federated loop aggregates both. This doubles the communication cost relative to CVAE‑F, which is the honest price.

The two losses, and the alternating update

ℒD = BCEWithLogits( D(xreal, y), 1 ) + BCEWithLogits( D(G(z,y).detach(), y), 0 )
ℒG = BCEWithLogits( D(G(z,y), y), 1 )     — the non-saturating form
(8)

Two details that get asked about. The .detach() in ℒD stops gradient flowing into G during the D step — without it, D's update would also modify G in the wrong direction. The non-saturating form means G maximises log D(G(z)) rather than minimising log(1 − D(G(z))); the latter has vanishing gradient exactly when G is performing badly, which is when gradient is most needed.

One DCGAN‑F training batchutils/localUpdateGen.py :: local_update_gan
# ---- D step ----
opt_d.zero_grad()
z    = randn(b, 50)
fake = net.G(z, y).detach()          # (b,32,16,16) — no grad to G
d_loss = BCE(net.D(x, y),    ones)  \
       + BCE(net.D(fake, y), zeros)
d_loss.backward(); opt_d.step()

# ---- G step: fresh noise, fresh graph ----
opt_g.zero_grad()
z    = randn(b, 50)
fake = net.G(z, y)                   # NOT detached this time
g_loss = BCE(net.D(fake, y), ones)
g_loss.backward(); opt_g.step()

The forward process — where the closed form comes from

A linear schedule of noise rates β1 = 10−4 to β200 = 0.02 defines

αt = 1 − βt,     āt = ∏s=1t αs    ⇒    q(xt | x0) = 𝒩( √āt x0,  (1−āt) I )
(9)

Because the composition of Gaussians is Gaussian, we can jump from x0 to any xt in one operation — no loop during training:

xt = √āt · x0  +  √(1 − āt) · ε,     ε ∼ 𝒩(0, I)
(10)

The training objective

The network predicts the noise that was added, not the clean signal:

ℒ = 𝔼t ∼ U[0,T),  ε ∼ 𝒩(0,I)  ‖ ε − εθ( xt,  t,  y ) ‖²2
(11)

Conditioning enters as an additive embedding: cond = time_embed(t) + label_embed(y), a 256-dim vector injected into every residual block via a learned linear projection. With probability 0.1 during training the label is replaced by a reserved null token (index C = 10, hence Embedding(11, 256)) so the model also learns the unconditional score — which is what makes classifier-free guidance possible at sampling time.

Reverse sampling with classifier-free guidance

ε̂ = (1 + w) · εθ(xt, t, y) − w · εθ(xt, t, ∅)
xt−1 = 1√αt ( xt − βt√(1−āt) ε̂ )  +  √βt · z,    z ∼ 𝒩(0,I) for t > 0
(12)

w = 0 means no guidance — one UNet pass per step, more diverse but lower-fidelity samples. w = 2 sharpens class identity at the cost of diversity and doubles the cost. The base paper finds w = 0 consistently outperforms w = 2 downstream, which they attribute to diversity mattering more than per-sample fidelity for augmentation.

Note the DDPM row in the conditioning table

DDPM‑F's label embedding has C + 1 = 11 rows: ten classes plus the reserved null token for classifier-free guidance. Mechanism A weights rows 0…9 by effective number and falls back to ordinary volume weighting for row 10, since the null token is not tied to any single class's frequency. That special case is handled explicitly in frequency_weighted_row_average via the num_conditioning_classes argument, and is exactly the kind of detail a careful examiner will probe.

Aggregation — two different rules in the same step

θfg ← 1|𝒞| Σk∈𝒞 θfk         θhg,m ← 1|𝒞m| Σk : mk=m θhk
(14)

F averages over all 10 clients. Headers average over the 4, 3 and 3 clients of each family separately. If a family has no participant this round, its previous global weights are carried forward unchanged.

What has changed when stage i ends

θfg is now a feature extractor that all ten clients agree on, trained on the union of their data through the proxy of their own headers. It is frozen from this moment and never updated again. Everything in stages ii and iii treats F as a fixed, deterministic function from images to features.

Feature extraction — what “frozen” means mechanically

Building the feature dataset at client kgefl_f/engine_f.py :: _stage_ii_round
fe.load_state_dict(fe_state)

Two distinct things happen here and both matter. fe.eval() switches BatchNorm to its running statistics so the same image always maps to the same feature. torch.no_grad() prevents the autograd graph from being constructed, so no gradient can reach θf even in principle.

Generator training — three different loops

From here the code branches on args.gen_model. All three share the signature (net, dataloader, args, opt_state) → (state_dict, avg_loss, opt_state), which is what lets the federated loop stay generator-agnostic.

vaeutils/localUpdateGen.py :: local_update_vae
for epoch in range(T_g = 5):
    for feat, y in feat_loader:              # (128,32,16,16), (128,)
        recon, mu, logvar = net(feat, y)      # forward: encode -> reparam -> decode
        loss = mse(recon, feat, sum) + kld(mu, logvar)
        loss.backward(); opt.step()
ganutils/localUpdateGen.py :: local_update_gan
for epoch in range(T_g = 5):
    for feat, y in feat_loader:
        # D step then G step, each with fresh noise (see 2.4)
        d_loss.backward(); opt_d.step()
        g_loss.backward(); opt_g.step()
# opt_state is a dict: {"G": ..., "D": ...} — two optimizers threaded per client
ddpmutils/localUpdateGen.py :: local_update_ddpm
for epoch in range(T_g = 5):
    for feat, y in feat_loader:
        loss = net(feat, y)      # forward() IS the loss — samples t, adds noise, predicts ε
        loss.backward(); opt.step()

Optimizer state is threaded across rounds per client. Client k's Adam moments are stored in gen_opt_states[k] and reloaded next round, matching the reference implementation's behaviour. This matters: Adam's second-moment estimate takes many steps to stabilise, and resetting it every round would cripple generator training.

05Stage iii traced — training the headers

TTN rounds. F and GF are both frozen; only headers learn. Mechanism B acts here.

1

Drawing the conditioning labels

Baseline: torch.randint(0, C, (B,)) — uniform, every class at probability 1/C = 0.1.

Mechanism B: compute the gated distribution, then draw from it.

Fidelity-gated samplerutils/label_sampler.py :: FidelityGatedSampler
g   = fidelity.mean()                                # scalar gate in [0,1]
inv = (1.0 / clip(natural_freq, 1e-6)) ** gamma      # inverse frequency
inv = inv * fidelity                                 # per-class quality scaling
inv = inv / inv.sum()
p   = (1 - g) * natural_freq + g * inv               # the blend
labels = np.random.choice(C, size=n, p=p / p.sum())

The point to make on the board

The tail class goes 0.113 early → 0.388 late, crossing the baseline's fixed 0.250. Early we ask for it less than uniform does, because the generator would return noise. Late we ask for it more, because now it can deliver. Mechanism B is a curriculum, not a reweighting — and note that uniform sampling was already over-representing the tail fivefold relative to π3 = 0.05. Anyone who says “uniform ignores imbalance” has it wrong.

2

Phase 1 — synthetic, Ts = 1 epoch

One synthetic batchgefl_f/engine_f.py :: _stage_iii_round
opt = fresh_optimizer(header.parameters())    # phase-local optimizer
for x_real, _ in loader:                     # iterate for batch COUNT only
    B      = x_real.size(0)                   # 128
    syn_y  = label_sampler.sample(B)          # (128,) from p(y)
    with torch.no_grad():
        syn_feat = gen_net.sample(syn_y)      # (128,32,16,16) — 1 pass, or 200 for DDPM
    logits = header(syn_feat)                 # (128,10)
    loss   = cross_entropy(logits, syn_y)
    loss.backward(); opt.step()
    accumulate softmax(logits)[i, syn_y[i]] into fid_sum[c], fid_n[c]

Note the loop iterates over the real loader but discards its contents — it is used purely to fix the number of synthetic batches at the same count as a real epoch, so synthetic and real exposure are directly comparable.

3

Fidelity accumulation — free, and applied once

p̄c = fid_sum[c] fid_n[c]      fc ← 0.6 · fc + 0.4 · p̄c     applied once, after the whole phase
(16)

Initial value fc = 0.15 for all c — deliberately pessimistic, so g ≈ 0.15 at round 1 and the sampler starts close to the natural distribution. Applying the EMA once per phase rather than per batch was a bug fix; per-batch updates made the estimate track within-epoch noise.

One real batchgefl_f/engine_f.py :: _stage_iii_round
opt = fresh_optimizer(header.parameters())    # reset again — momentum must not cross phases
for epoch in range(T_r = 5):
    for x, y in loader:
        with torch.no_grad():
            real_feat = fe(x)                 # (128,32,16,16) — frozen F
        loss = cross_entropy(header(real_feat), y)
        loss.backward(); opt.step()
Why the optimizer is reconstructed between phases

SGD with momentum 0.9 carries an exponentially-weighted average of past gradients. If the same optimizer spans both phases, the first few real-data steps are still being pushed in the direction the synthetic gradients pointed. The reference implementation constructs a fresh optimizer for the real phase; we did not, and fixing it was one of the six corrections needed before our reproduction matched the paper.

5

Aggregation

Headers only, grouped by family: θhg,m ← FlatAvg({θhk : mk = m}). θf and wg are untouched — nothing in stage iii can modify them.

06Evaluation

How every reported number is computed.

1

Build one evaluation model per client

For each of the 10 clients, wrap the frozen F and that client's family header into a single module. All clients of the same family produce identical models — the per-client loop exists so that per-client metrics remain available.

2

Forward the full balanced test set

All 10,000 CIFAR‑10 test images, 1,000 per class. The test set is never long-tailed — that is what makes tail accuracy interpretable, and it is a question worth pre-empting.

08Known deviations from the reference implementation

Stated openly. Every one of these is a question waiting to be asked.

Deviations, severity, and status
#DeviationConsequenceStatus
1 fe_channels = 32 rather than 3. Feature is (32,16,16) = 8192 dims versus the paper's (3,16,16) = 768. Feature is 2.67× larger than the image, not 4× smaller. Contradicts GeFL‑F's stated motivation; weakens the privacy argument. Open — add paper-matched config and report both
2 3 header families rather than 10 architectures. Numbers not directly comparable to paper Table II. Deliberate — compute budget. Documented.
3 nn.Embedding conditioning rather than one-hot concatenation. Gives Mechanism A a well-defined per-class row to reweight. The reference has no such row. Deliberate and necessary. Must be ablated to show the change alone does not explain the gain.
4 Upsample + Conv rather than ConvTranspose2d. Exact target sizes at any resolution; avoids checkerboard artifacts. Deliberate. Improvement.
5 n_T = 200, n_feat = 64 rather than 400/500 and 128. Under-trained diffusion; DDPM results not paper-comparable. Compute-driven. DDPM is a stretch goal.
6 No data augmentation. Lower absolute accuracy than augmented baselines. Deliberate — matches the paper's main tables.

Post-fix reproduction status

Balanced MNIST, GeFL, 20 rounds, 5 clients, 3 families: 93.76% overall, MND 0.625. Paper reports 94.46 ± 0.43% for FedCVAE on MNIST with ten architectures and a longer schedule; MND 0.714. Landing marginally below on accuracy with a smaller, shorter configuration is the expected direction, and the MND agreement is close. We treat the reproduction as sound.
